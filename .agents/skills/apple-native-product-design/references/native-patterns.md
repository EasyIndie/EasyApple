# 原生模式与验收

## macOS

- 系统拥有的输入源菜单、窗口交通灯、文件面板保持系统风格；不要伪装系统控件为品牌装饰。系统菜单跟随系统外观，应用覆盖不能改变它。
- 内容紧凑但可读；候选、表格、字段与正文分别量测中文/拉丁字形。菜单使用原生状态与快捷键；单修饰/不能表示的键位用静态辅助说明，避免制造不可执行快捷键。
- 独立任务窗口可以激活；浮动输入候选通常不能夺走客户端焦点。打开/关闭/失败都必须定义焦点返回对象和输入的保留/提交/取消规则。
- 多页设置按用户意图分组。已有Schema是配置真值，UI不能新增第二配置仓库；暂态状态与持久默认分别说明。即时保存不要另加虚假的提交按钮。
- 新系统优先自动获得原生最新外观；旧系统使用可用的标准材料。Liquid Glass不能替代文字可读性或让所有内容表面透明。

## iOS及跨项目

触控、键盘、多窗、屏幕尺寸不同，重新建立平台模式，不直接缩小Mac设置窗口。选项密度、目标尺寸、导航和安全区依设备决定。没有输入法/浮动辅助功能的项目不继承IMK焦点约束。

## 语义角色

最小令牌集合：canvas/surface/raised、text/secondary/disabled、separator/controlBorder、accent/onAccent、selection/selectionText/hover、error/errorFill、success/warning/focus。品牌色与状态色分开；如有图表需另定义类别/数值语义。

每个角色写使用位置、系统API及稿件参考值。亮暗+高对比四组，减少透明时用不透明表面，减少动态时去除非必要动画。实际系统强调色变化后重测，不能拿固定蓝色报告代替全部颜色。

## 证据矩阵

- 文字及操作：默认、hover、pressed、disabled、focus、loading、error、success、empty、长文本/极端数据。
- 外观：light/dark/increased contrast/reduced transparency/reduced motion；分隔装饰与必要边界分开计算。
- 对比项目目标可采用普通信息4.5:1、大字3:1、重要边界3:1；写明指标来源/用途与禁用例外。实际透明合成面另验。
- 键盘及辅助技术：名称/角色/值/状态/帮助/错误、逻辑Tab顺序、焦点可见、回到正确对象。浏览器aria检查与AppKit/SwiftUI实机VoiceOver是不同证据。
- 窗口环境：最小窗、不同字体/语言、RTL、多显示器缩放、全屏/Spaces、屏幕边缘及重开恢复。

信息错误优先行内且可恢复；模态只用于必须先决策的场景。破坏性操作准确指定对象，默认取消；不把“成功绿”当唯一反馈。
